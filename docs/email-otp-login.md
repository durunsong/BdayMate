# 邮箱验证码登录

## 目标与边界

登录页增加密码 / 邮箱验证码切换，默认保留密码登录。验证码仅登录已注册账户；持有正确验证码即证明邮箱所有权。注册、验证链接、找回密码和账户删除继续使用现有流程。设置页提供直接发送密码设置邮件的入口，支持首次通过 OTP 证明邮箱所有权后重新设置密码。无新依赖、无数据库迁移、无生产操作。

## 方案

复用 Better Auth emailOTP 插件和现有品牌邮件服务，避免自行实现认证会话或验证码存储。验证码 6 位、有效期 300 秒、哈希存储、最多 3 次错误尝试、成功后消费；重发轮换验证码。只开放插件的发送登录码与验证码登录用途，其他 OTP 用途不开放。

发送接口每 IP 每分钟最多 3 次，登录接口每分钟最多 10 次；沿用现有认证限流存储。页面发送冷却 60 秒，使用实际截止时间。未注册邮箱返回统一发送反馈，不自动创建账户。验证码模式使用现有 7 天会话，不显示插件不支持的“记住我”选项。

## 审查重点

验证码不出现在邮件日志或 URL；发送失败不能提示成功；更换邮箱清空验证码及成功提示；切换方式不绕过倒计时；正确码不可并发重复登录；原密码登录和注册验证不受影响。

## 审查修正

独立审查发现：Better Auth 会在未验证账户首次 OTP 登录时清除未证明归属的旧凭据与会话，避免邮箱抢注。保留该机制，在设置页解释并提供现有密码重置邮件入口；已登录用户无需退出账户即可设置密码。补充浏览器回归覆盖该分支和重设后的密码登录。

SMTP 失败传播采用仅针对发送登录码请求的 middleware context 覆盖，因为当前插件内部的默认后台任务包装器会捕获并吞掉发送异常。真实 SMTP 失败测试要求 HTTP 503 和安全错误码，其他认证请求保持现有行为。
