# 生日计算规则

入口为纯函数服务 BirthdayService（无 Prisma、网络或 server-only 依赖）。日期统一使用严格的 yyyy-MM-dd 格式；错误输入、超出支持范围、范围内找不到下一次生日时抛出 RangeError，调用方应展示错误，不应悄悄省略联系人。

- next(input, timeZone, now) 包含今天，从用户 IANA 时区的当前民用日期开始寻找下一次生日。
- between(input, start, end, timeZone) 包含两端，按日期升序返回；起止参数已经是该用户的民用日期，不再当作 UTC 时刻转换。
- daysUntil 是民用日期差；范围查询相对 start，下一次查询相对用户今天。以 UTC 日期表示相减，避免夏令时的 23/25 小时日影响。
- 时区交给运行时 Intl 的 IANA 数据验证，接受 UTC 及 IANA 别名，拒绝纯偏移值（如 +08:00）。
- SOLAR 的 birthYear 表示公历出生年，LUNAR 表示农历出生年；返回年龄为生日所属历法的年份减出生年份，属于该次生日将达到的年龄。未知年份返回 null。不会返回出生年之前的生日，出生当天年龄为 0。
- 公历范围为 0001–9999 年。2 月 29 日在非闰年默认按 2 月 28 日（FEB28），可选择 3 月 1 日（MAR1）；闰年仍为 2 月 29 日。
- 农历产品支持范围为农历 1900–2100 年完整年份，对应公历 **1900-01-31 至 2101-01-28**（含两端）。来源农历年、转换输入、查询范围均明确校验；这一边界是产品支持政策，不代表上游算法的全部覆盖范围。
- 按农历年枚举候选生日，再转公历，不将公历年直接当作农历年。一个公历年可能有同一联系人的两次农历生日，两次均保留。
- 闰月生日在有对应闰月的年份只在闰月出现一次；没有时默认在同名常规月过生日（REGULAR），也可跳过该农历年（SKIP）。SKIP 的下一次查询会继续寻找，不局限于下一年。
- 每年的农历月份只有 29 天时，周年日“三十”落在该月最后一天；未知出生年允许记录三十。已知出生年的原始日期必须真实存在，不允许通过闰月回退或月末截断把错误出生日期变合法。
- 公历转农历结果的月份为正数 1–12，闰月另用 isLeapMonth 表示。适配层内部才使用上游库的负数闰月编码。
- 农历转换采用中国历法的民用日期；用户时区决定“今天”和提醒日期，不重新按用户所在地计算天文朔日。持久化提醒时间转换为 UTC 的职责属于调度层。
- 日历网格和统计年可以与农历支持区间部分重叠；页面只查询交集，并明确显示覆盖范围，不因网格边缘越界而丢弃区间内的有效生日。服务 `between` 本身仍严格拒绝越界端点。年份选择包含 2101 年，以展示农历 2100 年末的生日。
- Dashboard 的今日、未来 7/30 天及年龄按本次渲染的用户民用日期重新计算，避免沿用先前服务器响应中的 `daysUntil`。未来天数沿用包含今天和第 7/30 天的口径；联系人总数与统计排除归档记录。每月分布保留同一联系人在同一公历年的两次农历生日。计算异常在统计旁明确提示。

## 依据与验证

- 上游 API：[lunar-javascript / 6tail](https://6tail.cn/calendar/api.html)。适配层只使用 Lunar、LunarMonth、Solar 的日期转换与月长 API。
- 产品日历基准：香港天文台[公历与农历对照表（1901–2100）](https://www.hko.gov.hk/sc/gts/time/conversion.htm)当前公开版本。2026-11-14 实际获取 200 份官方年度文字表，覆盖公历 **1901-01-01 至 2100-12-31，共 73,049 天、2,474 个农历月起点**。精简独立 fixture 位于 `tests/fixtures/hko-calendar.json`，保存起止日期、月起点、抓取日期与每份原始文件 SHA-256，不依赖待测库生成期望值，也不保存完整年度原文。
- 本次发现上游与官方表的唯一差异区间为 **2057-09-28 至 2057-10-27**：官方 [2057 年文字表](https://www.hko.gov.hk/en/gts/time/calendar/text/files/T2057e.txt)以 9 月 28 日为农历九月初一，八月 29 天、九月 30 天；上游月界晚一天。适配层只对这一月界校准，正向/反向转换、月长、源日期校验及“三十”周年截断保持同一基准。
- 香港天文台在对照表说明中明确指出：数十年后的朔日若接近午夜，月相计算的分钟级不确定性可造成一天之差；特别列出 **2057-09-28、2089-09-04、2097-08-07**。校准表示与当前公开日历一致，不表示无限未来或将来修订后的天文绝对精度。上游升级或官方表更新后须重新核对。
- 官方表不包含公历 1900 年和 2101 年。产品在 **1900-01-31 至 1900-12-31、2101-01-01 至 2101-01-28** 的额外覆盖只做逐日往返一致性与边界测试，不能把这部分描述为经过 HKO 独立逐日验证。
- `pnpm exec vitest run tests/unit/birthday.test.ts tests/unit/birthday-hko.test.ts tests/unit/birthday-views.test.ts`：覆盖春节跨年、同公历年两次生日、闰月 REGULAR/SKIP、月末、二月二十九、已知出生年与年龄、范围边界、DST；独立 fixture 校验每个官方月的首末日/月长和月首生日；真实 React 服务端渲染验证统计与月历。
- `pnpm exec tsx scripts/verify-hko-calendar.ts`：离线按独立 fixture 对全部 73,049 天执行双向转换比较。`--refresh` 重新获取全部官方年度表并更新精简 fixture；随后执行同样的全量比较。命令失败必须检查数据变化，不应机械删除差异。测试和脚本均不访问业务数据库、不发送邮件。
