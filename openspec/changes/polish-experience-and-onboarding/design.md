# 设计与实现决定

## 视觉与交互

延展既有品牌，不重做业务布局。日光主题保留温暖浅底，夜色主题使用深靛色底、层次化表面和可读紫色；提供跟随系统、日光、夜色三种偏好，持久化并同步标签页。首次渲染前应用主题避免闪白；有原生 View Transition 支持时从主题控件展开柔和圆形过渡，否则平滑颜色切换。减少动态效果时直接切换。

顶部细线进度覆盖真实站内导航，带流光和端点光芒，不伪造百分比；到达页面结束，超时有兜底清理。保留既有骨架屏。共享 Button 的图标、文字、加载状态保持单行居中与尺寸稳定，暴露 aria-busy。

首页以“把在乎，放进日历”为中心，使用一个可交互的生日轨道/日历场景与有节奏的滚动叙事；公开产品解释、可操作的体验演示、真实功能及注册入口，不伪造用户数、评价或真实联系人。大动作集中于首页，后台以效率为主。

## 注册与邮件

注册完成明确提示去收件箱点击邮件按钮；提供可信常见邮箱入口、重发冷却、垃圾箱提示、修改邮箱返回入口及真实验证状态检查。只有服务端认证确认成功才显示成功，保留邮件 callback 的实际验证链路。已验证会话访问 login/register/forgot-password 重定向 dashboard；验证回调和持有效重置令牌流程保持可用。

统一品牌信纸邮件，验证、重置、本人提醒、联系人祝福具有适合语义的标题区、内容区和 CTA；表格/内联样式兼容常见邮箱，无 JavaScript、无跟踪。联系人自定义正文与默认祝福改进，预览只展示对方将收到的内容，保留隐私边界。HTML 和纯文本都保留必要链接及内容。

## 验证与边界

最小行为回归先失败后实现。浏览器覆盖主题持久化/系统偏好/减少动态/移动无溢出，路由进度真实延迟导航与结束，加载按钮布局，完整注册→本地 SMTP 验证邮件→真实验证→登录后路由拦截，邮件和祝福预览内容。只用精确隔离测试账号与本地邮件捕获，清理测试数据；提交前全套测试、lint、typecheck、格式、构建与编码/秘密差异检查。GitHub/Vercel发布沿用已经授权的 main 与开发分支，不强推。
